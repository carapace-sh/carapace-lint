# carapace-lint

[golangci-lint](https://golangci-lint.run) module plugin that lints
[carapace](https://github.com/carapace-sh/carapace) command definitions.

## Checks

| Settings key         | Analyzer           | Description                                                            |
|----------------------|--------------------|------------------------------------------------------------------------|
| `flags-order`        | `FlagsOrder`       | flags defined with `cmd.Flags().<Type>(...)` have to be sorted         |
| `flag-actions-order` | `FlagActionsOrder` | entries of `FlagCompletion(carapace.ActionMap{...})` have to be sorted |
| `macro-syntax`       | `MacroSyntax`      | public actions have to match the macro syntax                          |
| `completion-values`  | `CompletionValues` | completion values have to be paired correctly, be unique and sorted naturally |

## Macro syntax

Macros are generated by scanning package documentation for
`func ActionX(...) carapace.Action`, so a public action is only available as macro
if its signature is one of:

| Signature      | Macro  |
|----------------|--------|
| `ActionX()`    | MacroN |
| `ActionX(t)`   | MacroI |
| `ActionX(t...)`| MacroV |

Everything else can't be represented as macro (the generator emits
`// TODO unsupported signature`), typically a function taking multiple parameters:

```go
func ActionWindows(server, session string) carapace.Action // not available as macro
```

`MacroSyntax` reports exported `Action*` functions in the configured paths that
don't match this syntax, that are missing a doc comment (it becomes the macro
description), or exported functions returning `carapace.Action` without the `Action`
prefix. Functions of other packages (e.g. completers defining `cmd/action` helpers)
are ignored, as are methods and test files.

## Completion values

Actions taking values expect a fixed number of arguments per entry:

| Action                        | Arguments                  |
|-------------------------------|----------------------------|
| `ActionStyles`                | style                      |
| `ActionValues`                | value                      |
| `ActionValuesDescribed`       | value, description         |
| `ActionStyledValues`          | value, style               |
| `ActionStyledValuesDescribed` | value, description, style  |

`CompletionValues` reports calls with a wrong argument count (carapace would render
`invalid amount of arguments` instead of completions), entries defined multiple
times within the same call, which show up as duplicate menu entries, and entries
that are not sorted. Sorting is natural order: alphabetical, with runs of digits
compared numerically, so F2 sorts before F10. The same value
with a different description or style is allowed, as carapace distinguishes entries
by value and description. Values that are only known at runtime are ignored,
and sorting is only checked between entries that are defined statically next to each other.
Lists whose values are all numeric or size-like (512, 2k, 2.5MiB) are ordered
by magnitude instead, so sizes ascend naturally; a single different value
falls the whole list back to the natural order.

Deliberately ordered lists are marked with a `// carapace:curated` comment inside
the call, which exempts them from the sorting check (arity and duplicates still
apply) — on the call's line for multiline lists, after the call for single-line
lists:

```go
return carapace.ActionValues( // carapace:curated
	"on", "off", "gzip", "gzip-1", "zstd", "zstd-fast",
)
```

The marker works in the standalone binary as well; `//nolint:carapace`
suppression and grouping via `Batch` remain available.

## Ordering checks

Both ordering checks group consecutive definitions, so blank lines (and comments)
separate independent blocks and single definitions are ignored. Multi-line definitions
are supported.

Suggested fixes are provided for the ordering checks, for duplicate completion
entries and for unsorted completion values and are applied by `golangci-lint run --fix`.
Reordered blocks are formatted in place, so the result stays compatible with `gofmt`.
A fix is not offered when it can't be applied safely, e.g. when a definition shares a line
with other code, is preceded by a comment, or when formatting would affect other lines.
Unsorted completion values are sorted by their value, and the fix is skipped when the same
call has duplicate entries, as their removal touches the same lines: a second run (or
running `--fix` again) then sorts the remaining ones. Entries are moved together with
their descriptions and styles, whether they are written one per line or next to each
other on the same line; sharing a line with other code doesn't block the fix,
as only the entries themselves are replaced, but comments between entries do.
Duplicate entries are removed together with one adjacent comma, including a comment on
the same line when one follows the comma. The removal ranges never overlap, so several
duplicates within one call are fixed together; entries are skipped when a comment line
above the entry would be affected or the file cannot be read.
The issue is reported nonetheless.

Only flags registered via `cmd.Flags()` are checked, `PersistentFlags()` is ignored
(same as the linter this replaces).

## Usage

Module plugins have to be compiled into a custom golangci-lint binary:

```shell
golangci-lint custom
./custom-gcl run ./...
```

[golangci-lint-action](https://github.com/golangci/golangci-lint-action) v9 and later build
the module plugins automatically when it detects the `.custom-gcl.yml` in the repository.

`.custom-gcl.yml`:

```yaml
version: v2.15.0
plugins:
  - module: github.com/carapace-sh/carapace-lint
    import: github.com/carapace-sh/carapace-lint
    version: latest

  # or a local checkout
  # - module: github.com/carapace-sh/carapace-lint
  #   path: ../carapace-lint
```

`.golangci.yml`:

```yaml
version: "2"

linters:
  default: none
  enable:
    - carapace
  settings:
    custom:
      carapace:
        type: module
        description: check carapace command definitions
        original-url: https://github.com/carapace-sh/carapace-lint
        settings:
          flags-order: true
          flag-actions-order: true
          macro-syntax: true
          completion-values: true
```

The linter name (`carapace` above) has to match the registered plugin name.
`carapace-lint` is registered as an alias if you prefer that name.

Issues are reported per analyzer, e.g.:

```text
main.go:26:2: FlagsOrder: flag "alpha" should be sorted before "beta" (carapace)
main.go:30:3: FlagActionsOrder: flag completion "alpha" should be sorted before "zeta" (carapace)
main.go:12:6: MacroSyntax: public action "ActionWindows" should take at most one parameter to match the macro syntax (carapace)
main.go:40:3: CompletionValues: duplicate completion entry "a" (carapace)
main.go:44:3: CompletionValues: completion value "alpha" should be sorted before "zeta" (carapace)
```

Files can be excluded with the usual golangci-lint mechanisms, e.g. to skip tests:

```yaml
linters:
  exclusions:
    rules:
      - path: (.+)_test\.go
        linters:
          - carapace
```

## Standalone binary

Released binaries run all checks with default settings, without golangci-lint:

```shell
go install github.com/carapace-sh/carapace-lint/cmd/carapace-lint@latest
carapace-lint ./...
carapace-lint -fix ./...
carapace-lint --version
```

The binary is a regular analysis driver, so `-fix`, `-json`, `help [analyzer]` and the
per-analyzer `-<Analyzer>=false` flags are available. Settings like `macro-syntax-paths`
and `//nolint` suppression are only available through the golangci-lint plugin.

## Settings

| Key                  | Type     | Default                     | Description                                     |
|----------------------|----------|-----------------------------|-------------------------------------------------|
| `flags-order`        | bool     | `true`                      | check alphabetical order of flag definitions    |
| `flag-actions-order` | bool     | `true`                      | check alphabetical order of flag completions    |
| `macro-syntax`       | bool     | `true`                      | check that public actions match the macro syntax |
| `macro-syntax-paths` | []string | `["(^|/)pkg/actions(/|$)"]` | file patterns providing public actions          |
| `completion-values`  | bool     | `true`                      | check completion values                         |

Patterns are matched against the file path. Unknown keys are rejected.

## CI

SARIF reports, code scanning and pull request annotations are provided by
golangci-lint itself and don't need to be handled by the plugin:

```yaml
output:
  formats:
    sarif:
      path: golangci-lint.sarif
```

```shell
./custom-gcl run --fix ./...
```

```yaml
- uses: github/codeql-action/upload-sarif@v4
  with:
    sarif_file: golangci-lint.sarif
```

## Development

```shell
go test ./...
```

The analyzers are tested with
[analysistest](https://pkg.go.dev/golang.org/x/tools/go/analysis/analysistest),
including the suggested fixes (`testdata/src/*/*.go.golden`).
